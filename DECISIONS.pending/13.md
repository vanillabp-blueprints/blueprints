# CI reads every VanillaBP snapshot without a login

This repository keeps no decision log, so this file only makes the decision visible when the
branch is merged. Dropping it is a fine outcome.

## What was decided

The two Camunda adapters now publish their snapshots to the snapshot repository of Maven Central,
like the rest of VanillaBP. So nothing in this repository reads GitHub Packages any more, and:

- The settings file of the CI lost the two repositories and their credentials. It is now called
  `.github/workflows/maven-settings.xml`, because the old name named GitHub Packages.
- `build.yaml` and `nightly.yaml` no longer pass `VANILLABP_USER_NAME` and `VANILLABP_USER_TOKEN`,
  and the nightly no longer stops when they are empty. This repository no longer needs the two
  secrets. They are not secrets of this repository, so other repositories of the organisation
  may still read them.
- `bin/camunda8_cluster.sh` uses that settings file when `CI` is set, instead of when `USER_TOKEN`
  is set. Locally it still uses your own Maven settings. With the settings file a local run would
  replace an adapter you installed yourself with the published one.
- `bin/platform_snapshot.sh` now also lists the adapters. It reads what came from
  `central-snapshots`, and that is where the adapters come from now.

# The host of the module kit checks the names, not the dev shell

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule now lives in the
README of `cockpit-process-driver-frontend/react`, in the section `The dev shell plays the cockpit`.
This file makes the decision visible when the branch is merged. Nothing cites it, so dropping it
is fine.

## What was decided

- The six cockpit frontends use `@vanillabp/bc-module-kit` and `@vanillabp/bc-module-host`
  `0.1.0-snapshot.5`.
- The host of that snapshot checks the names of the web components before it loads anything, the
  way a cockpit does, and throws a `BcHostError` with the code `WRONG_ELEMENT_NAME`. So the dev
  shell of `cockpit-process-driver-frontend` no longer checks them itself:
  `dev-shell/src/element-names.ts` is gone, and the page of a user task shows the message of the
  host. This replaces the point about the dev shell in `1886.md`.
- The browser tests of `cockpit-user-task-frontend/react` show a new build of the module loading
  without a reload of the page, with a short `manifestRecheckMs`.

## Who decided

The Business Cockpit team, 2026-11-19, once the module kit had the check.

# A test root runs the scoping mode of its application

This repository keeps no decision log, so this file only makes the decision visible when the
branch is merged. Dropping it is a fine outcome.

## What was decided

A module test runs under the BPMS profile of the build, but it reads the profile files of its
own source root. Where that root had no `application-camunda7.yaml`, the test ran `camunda7`
under the default `by-adapter`, while the application ran `use-prefix`. The test roots now copy
the application. Each one has a profile file for every BPMS whose application profile names a
mode, and that file names the same mode.

`bin/check_scoping_modes.py` now compares every profile of every source root of a blueprint,
main and test together. A difference between main and test is an error, not a warning. Story
704 came from exactly this gap: a test which runs another configuration than the one the
blueprint ships.

## What it found

42 test source roots in 36 blueprint directories ran `camunda7` under the default. 41 had no
`application-camunda7.yaml`, and one, in `module-idle-application/springboot`, had the file
without the mode. All of them now name `use-prefix`.

Out of scope: the Quarkus twins of the `bpmn-*` blueprints and of `module-idle-application`
have no `camunda7` mode at all. So on Quarkus both the application and the test run Camunda 7
under `by-adapter`, while the Spring Boot twins run `use-prefix`. The check sees no difference
inside one twin, so it says nothing about that.

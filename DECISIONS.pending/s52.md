# Every API of a blueprint is written as an OpenAPI file

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself now lives
in `CONTRIBUTING.md`, rule 7. This file makes the decision visible when the branch is merged.
Nothing cites it, so dropping it is fine.

## What was decided

Every HTTP interface of a blueprint is an OpenAPI file first, and the build generates the Java
code from it. No path, parameter annotation or record of a request or an answer is written by
hand. An API with a Java client gets a Maven module `<name>-api` with `client` and `server`. An
API which only a browser or the module's own user interface calls keeps its file in the module,
at `src/main/resources/openapi/<use-case>.yaml`. That includes every `ApiController`.

The details were decided while the rule was applied:

- The file is in `src/main/resources/openapi/`, where the cockpit blueprints had it already,
  because their frontends read it from there. It is the second file outside the directory of
  the workflow module ID. Its name is the use case, so it does not clash.
- Spring Boot generates with `spring`, Quarkus with `jaxrs-spec`. Both write an interface only.
  The paths in the file are complete and the server is `http://localhost:8080`, so the
  interface needs no path of its own.
- The cockpit forms keep the server `/wm/<module-id>` of the cockpit in their file. Their
  controller puts the path of the module in front with a `@RequestMapping` of its own.
- A type the framework already has, such as `WorkflowHistory`, is described in the file and
  mapped to that type with `schemaMappings`.
- The tests of the cockpit blueprints still read the official API of the cockpit with a plain
  `RestClient`. The cockpit publishes no client for that API.

## Who decided

Stephan, 2026-11-14: "Alle APIs auf das API-first Muster (Open-API-Spezifikation mit client und
server Maven-Modul) umstellen. Wenn es eine eigene API ist und der Client nur im Typescript in
der eigenen UI ist, dann kann die OpenAPI-Spezifikation auch direkt im Modul mit dem
implementierenden RestController liegen." He confirmed that this holds for the `ApiController`
of every blueprint.

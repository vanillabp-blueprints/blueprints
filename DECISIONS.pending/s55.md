# The cockpit frontends generate their API client with typescript-fetch, at every build

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself now lives
in `CONTRIBUTING.md`, rule 7. This file makes the decision visible when the branch is merged.
Nothing cites it, so dropping it is fine.

## What was decided

The frontends of the cockpit blueprints, `blueprints-cockpit/*-frontend/<framework>`, call the
API of their workflow module. Until now they used `openapi-fetch` with types which
`openapi-typescript` wrote from the OpenAPI file. The calls themselves were written by hand, as
paths in strings.

Now the OpenAPI Generator with the generator `typescript-fetch` writes the whole client. This is
the tool the backends use for their Java code. Its names follow the OpenAPI file in the same way:
the tag `user-tasks` becomes the class `UserTasksApi`, an operation becomes a method of it, and a
schema becomes a type. The first server of the file becomes the base path of the client.

- The generator runs at every build, from `npm run generate:client`, and writes to
  `src/generated/`, which git ignores. This is what the backends do with their Java code below
  `target/`. So the OpenAPI file stays the only source, and a changed API breaks the build of the
  frontend instead of the form in the browser.
- The npm package `@openapitools/openapi-generator-cli` downloads the generator from Maven Central
  and runs it. `openapitools.json` pins the generator to the version the backends use.
- The generator is a Java program. So the build agent of a frontend needs a Java runtime next to
  Node. It still needs no Maven and no `pom.xml`. Before this change, the READMEs said a frontend
  builds "with npm and nothing else". That is no longer true, and the READMEs and `frontend.yaml`
  now say so.

## What was not chosen

The other choice was to commit the generated code. Then the build agent needs no Java, but every
move of the git submodule `backend` needs a developer with Java to generate again, and nothing
stops a client which no longer fits the OpenAPI file. The Java code is not committed either.

## Who decided

Stephan, 2026-11-14, in the review of blueprints#149: "Es soll dieser Generator verwendet werden:
https://openapi-generator.tech/docs/generators/typescript-fetch/. Da kommen, analog zu Java,
benannte Klassen heraus." Generating at every build instead of committing the code follows the
Java side. The Java runtime this needs on the build agent of a frontend is a consequence he has
not ruled on yet.

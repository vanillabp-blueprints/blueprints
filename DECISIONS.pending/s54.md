# A client module brings the configuration which builds its client

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself lives in
`CONTRIBUTING.md`, rule 7. This file makes the decision visible when the branch is merged.
Nothing cites it, so dropping it is fine.

## What was decided

Every `client` module of an `<name>-api` module brings the configuration which builds its
client. An application adds the dependency, sets the properties and injects the generated
interface. It writes no client configuration of its own.

- On Spring Boot the module has an AutoConfiguration which extends `ClientsConfigurationBase`
  of `business-cockpit-spring-boot-support`. Its properties class extends `Client` of the same
  library, so all clients have the same keys.
- `ClientsConfigurationBase` builds OpenFeign clients. So a client module generates with the
  generator `java` and the library `feign`, the way the cockpit's own `bpms-api-client` is
  generated. Project M uses the generator `spring` with the library `spring-cloud` and builds
  its clients with Spring Cloud's `FeignClientBuilder`. That way would bypass
  `ClientsConfigurationBase` and need Spring Cloud, so the blueprints do not follow it.
- The `java` generator knows no records. The models of a client are classes with getters,
  while the models of a server stay records. It also needs a few supporting files with Jackson 2
  imports. Only the marker interface `ApiClient.Api` of them is used. The JSON is read with the
  Jackson 3 mapper of the application.
- Most answers of the simulator's test API are plain text. The JSON decoder of the support
  fails on a plain text answer, so the client of the test API reads a `String` as text. It
  overrides `configureJsonEncoding` for that.
- On Quarkus the module has a bean producer and a `@ConfigMapping` with the same key names
  (`base-url`, `connect-timeout`, `read-timeout`), and the REST client of Quarkus implements
  the interface. When the support has a Quarkus module, the producer moves onto it.
- The tests read the official API of the cockpit with the classes the cockpit generates from it,
  `official-gui-api-server`: the path constant of `OfficialTasklistApi` and the model
  `UserTask`, instead of a map. The cockpit publishes no Java client of that API, so the request
  itself is still sent by the HTTP client of the tests.

## Who decided

Stephan, 2026-11-14, in his review of blueprints#149: "Wenn die Schnittstelle ein eigenes
Client-Modul hat, wie bei den Blueprints, packen wir das als AutoConfiguration dort hinein. Dann
muss man nur die Dependency ziehen und in der application.yaml die richtigen Properties setzen.
Fuer diese RestClient-Konfigurations gibt es eben aus dem support/spring-boot die
ClientsConfigurationBase". The generator, the Quarkus counterpart and the handling of plain text
answers were decided while the rule was applied, with the defaults of the story.

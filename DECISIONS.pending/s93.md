# Pull requests build on Camunda 7, the night builds every engine

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself now lives
in `CONTRIBUTING.md`, in the section `What a pull request builds, and what only the night
builds`. This file makes the decision visible when the branch is merged. Nothing cites it, so
dropping it is fine.

## What was decided

- A pull request builds each blueprint it touches on Camunda 7 only. That is about 80 jobs
  instead of more than 300. `bin/build_matrix.py --engine camunda7` narrows the list, and
  `build.yaml`, `cockpit-applications.yaml` and `cockpit-application-proxy.yaml` pass it for a
  pull request.
- A push to `main` and the nightly build test every engine, as before.
- The jobs without an engine (`checks.yaml`, `frontend.yaml`, the aggregator `monorepo`) are
  unchanged.
- A blueprint which does not run on Camunda 7, such as one for Camunda 8 only, builds on the
  first engine of its index entry in a pull request. Without that, a pull request which changes
  only such a blueprint would test nothing of it. This point was not part of the decision below
  and is open to review.
- `nightly.yaml` already existed and builds every blueprint on every engine. It does not reach
  the applications and bundles of the cockpit blueprints, because `build.yaml` leaves them out.
  So `cockpit-applications.yaml` and `cockpit-application-proxy.yaml` got a schedule of their
  own, half an hour after the nightly build. They are not watched by `nightly-issue.yaml`.

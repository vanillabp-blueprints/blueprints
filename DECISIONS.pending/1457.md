# The Vue frontend compiles its components with esbuild, not with Vite

This repository keeps no decision log, so this file only makes the decision visible when the
branch is merged. Dropping it is a fine outcome.

## What was decided

`blueprints-cockpit/cockpit-user-task-frontend/vue` writes its components as Vue single-file
components (`.vue`). The skill `business-cockpit-user-interface` suggests Vite in library mode
with `@vitejs/plugin-vue` for Vue. This frontend uses esbuild instead, like the React and the
Angular frontend:

- `scripts/build-micro-frontends.mjs` has a plugin of about fifteen lines. It hands every `.vue`
  file to `vue/compiler-sfc`, which comes with the package `vue`, and bundles the TypeScript it
  gets back. There is no extra dependency for the build.
- So the three frontends share the same scripts, the same entry list and the same esbuild
  metafile, and `bc-check-entries --metafile build/meta.json` works the same way in all three.
  The kit's check reads an esbuild metafile, not the manifest of Vite.
- A `<style>` block in a component fails the build. The styles go into `src/shared/style.ts`, and
  `src/shared/vue-element.ts` puts them into each shadow root, as in the other two frontends.
- `npm run typecheck` runs `vue-tsc`. It checks the templates without `strictTemplates`, because
  that option rejects every `data-testid`, which the type definitions of Vue do not know. Unknown
  components, directives and events are still errors.

Each web component gets a small Vue application of its own with `createApp`. The properties of
the cockpit go in through `provide` as one shallow ref, and `useBcElement()` reads them.

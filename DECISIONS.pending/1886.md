# The cockpit frontends name their web components per build

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself now lives
in the README and the AGENTS.md of each cockpit frontend, in the section `The names of the web
components`. This file makes the decision visible when the branch is merged. Nothing cites it,
so dropping it is fine.

## What was decided

- All six cockpit frontends build the names of their web components with `createElementNames`
  of `@vanillabp/bc-module-kit`, as `elementName` in `src/loan-approval.ts`. A name is the prefix
  of the workflow module id, the id of the build and the short name.
- The forms of user tasks use `userTask(BPMN_PROCESS_ID, taskDefinition, part)`. The part is
  `form` for the area `all` and the name of the area for the others, so "Assess risk" gives
  `loan-approval-<build id>-loan-approval--assess-risk--form` and `...--assess-risk--body`.
- The case page uses `workflow(BPMN_PROCESS_ID, part)`, with `page` for the area `all`:
  `loan-approval-<build id>-loan-approval--page`.
- The header extension uses `custom('request-loan-button')` and `custom('request-loan-form')`,
  because the button and the start form show no workflow and no user task.
- `scripts/write-bc-build.mjs` writes `src/bc-build.js` before the type check, with
  `WORKFLOW_MODULE_ID` from `config.workflowModuleId` in `package.json` and `BUILD_ID`.
  `scripts/build-micro-frontends.mjs` reads the time back from `BUILD_ID` for `createManifest`, so
  both use one time without passing it between two processes. The file is not checked in, and
  `src/bc-build.d.ts` holds its types.
- The dev shell of `cockpit-process-driver-frontend` checks the names before it draws a form, the
  way a cockpit does, in `dev-shell/src/element-names.ts`. The host of the kit does not check
  names. So the dev shell asks the data entry first, and the host asks it again when it draws.

## Who decided

The Business Cockpit team, 2026-11-18, once the module kit had the helper. The rule for the
names comes from the skill `business-cockpit-creator` and the module kit. The parts `form` and
`page` and the place of the check are choices of this change and open to review.

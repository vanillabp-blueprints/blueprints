# User tasks in the application: how the blueprint is cut

This repository keeps no decision log, as `CONTRIBUTING.md` explains. This file makes the
decisions of the blueprint `cockpit-usertasks-in-the-application` visible when the branch is
merged. Nothing cites it, so dropping it is fine.

## What was decided

The blueprint is in the category `cockpit`, although nothing in it talks to the Business
Cockpit. Its patterns hold for any application with forms of its own. The category was chosen
because the cockpit blueprints start on one platform and get their twins later, and this
blueprint has no twin yet. Once it has one, it may move to the category `bpmn`.

Its base is `bpmn-user-task`, the simple case. The README says when the simple case is enough.

The endpoints of a form are GET to read, PUT to save a draft and POST to complete. A form sends
what a user entered, and that does not belong in a URL. Starting and looking at a loan approval
stay GET, so a person can do that in a browser. Without a form, the README shows `curl` in its
place.

`TaskData` is stored as JSON by a JPA `AttributeConverter` with Jackson. No library for JSON
columns is needed, and it works with every database. The records are replaced as a whole, so the
persistence layer sees a different value on every save.

Two branches of the workflow write to the aggregate. The blueprint uses `@DynamicUpdate` and
not `@Version`, because the branches write different columns and tables. A version attribute
would turn every task created at the same moment into a collision, and the forms would have to
retry.

The protection of the endpoints (pattern 1.c of the list) is a section of this blueprint, not a
blueprint of its own: one authority per kind of user task, checked with `@Secured` in the module,
and a second check of the kind of the task in `Service`. How users log in is the application's
part. Roles mapped to authorities are left to `cockpit-roles-and-permissions`.

A canceled user task is shown by a terminate end event, which works on every BPMS. The
withdrawal of the base blueprint uses `cancelUserTask`, which Camunda 8 does not support.

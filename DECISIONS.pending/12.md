# Injected beans are named after their role, not after their type

This repository keeps no decision log, as `CONTRIBUTING.md` explains. The rule itself now lives
in `CONTRIBUTING.md`, rule 2. This file makes the decision visible when the branch is merged.
Nothing cites it, so dropping it is fine.

## What was decided

Inside a bean, an injected bean is named after the role it plays in that bean. Its type does
not give the name. A call then reads like a short sentence about the business case:
`loanApproval.assessCreditRating(loanRequest)` instead of `service.assessCreditRating(loanApproval)`.

Every blueprint uses the same names:

- The use case's `Service` is named after the use case, singular. In the loan approval
  blueprints that is `loanApproval`.
- `ProcessService` is `bpms`.
- `Workflow` stays `workflow`, and a repository keeps the plural of what it stores, such as
  `loanApprovals`. Both followed the rule already.

Where a method parameter or a local variable would hide the new field, it gets a name of its
own from the domain. The aggregate of a loan approval is `loanRequest`. The words `request`
and `application` alone were rejected, because both already mean something else in IT.

`Service#initiateLoanApproval` became `Service#request`, so the controller reads
`loanApproval.request(loanRequestId, amount)`. The start methods of the other use cases
follow where the call would repeat the field: `initiateRepayment` became `initiate`, and
`requestCreditHistory` and `requestReview` became `request`.

Every other service method whose call would repeat the field name drops that part too. So
`loanApproval.getLoanApproval(id)` became `loanApproval.get(id)` and
`loanApproval.loanApprovalClosed(...)` became `loanApproval.closed(...)`. The other use cases
follow the same way. A method whose name does not repeat the field keeps its name.

## Why

Most readers of a blueprint copy it. A name copied from here ends up in many applications,
so it should explain the code. `service` and `processService` only repeat the type, which the
declaration already shows. The role is what a reader cannot see from the declaration.
